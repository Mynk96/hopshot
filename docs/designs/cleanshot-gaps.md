## PR 2 — Window capture (PRD F1.6), desktop 0.1.15

### What already exists (reuse, don't rebuild)
- Frozen frames per monitor: `capture/frames.rs` `grab_all()` / `FrozenFrames`.
- Logical→physical crop per monitor, with tests at 1.0/1.25/1.5/2.0 and negative origins: `capture/crop.rs` `to_physical`.
- Commit path: overlay sends `overlay_commit {monitorId, rect}` → `capture::commit` → PNG → shelf. Free-plan cap, stats and auto-sync already sit on this path.
- Overlay payload: `capture/overlay.rs` `OverlayStart` / `start_payload`.
- Platform split: `platform/macos.rs`, `platform/windows.rs`; `core-graphics` (macOS) and `xcap` already in Cargo.toml.
- **One direct dependency, macOS only: `core-foundation = "0.10"`** (rule 5 justification: already in Cargo.lock via core-graphics; needed to read `kCGWindowLayer`/`kCGWindowOwnerPID`/`kCGWindowAlpha` as CFNumber and `kCGWindowBounds` from the untyped CFArray that `core_graphics::window::copy_window_info` returns; the alternative is hand-written unsafe FFI).

### Architecture

```
hotkey / tray "Capture window"
        │
        ▼
capture::start(mode) ──► permissions check (unchanged)
        │
        ├─► window_list::snapshot()                 NEW (capture/window_list.rs)
        │      ├─ platform::list_windows()          NEW per OS, front-to-back, global coords
        │      │    macOS: one copy_window_info(OnScreenOnly | ExcludeDesktopElements) call;
        │      │           keep layer==0, alpha>0, drop own pid
        │      │    Windows: xcap::Window::all() (drops invisible, cloaked, untitled tool
        │      │           windows, own pid, Progman), then also drop classes Shell_TrayWnd,
        │      │           Shell_SecondaryTrayWnd, WorkerW and any WS_EX_TOOLWINDOW, and minimized
        │      ├─ to_local(global, &MonitorBounds) per monitor → clipped LogicalRect
        │      └─ drop < 24×24 logical AFTER clipping
        │
        ├─► frames::grab_all()                      unchanged; stored with each Frame:
        │                                           its windows + start_in_window_mode
        ▼
overlay::start_payload(frame, nonce)  ─ also used by pending() ─►  + `windows: Vec<LogicalRect>`
        │                                                            + `startInWindowMode: bool`
        ▼
Overlay.tsx  ── Space toggles ──►  region mode  ⇄  window mode
                                   (drag rect)     (hover: draw highlight for the topmost rect
                                                    under the pointer; click/Enter: send index)
        │
        ├─ region:  overlay_commit {monitorId, rect}            ──┐
        └─ window:  overlay_commit_window {monitorId, index} ─────┤ Rust looks up the stored rect
                                                                  ▼
                    capture::commit ──► crop::to_physical ──► Frame::crop ──► shelf (unchanged)
```

Snapshot runs immediately before `grab_all()` while overlays are hidden; a window that moves in that gap of a few ms is accepted. The per-monitor rects and the mode live in `FrozenFrames` next to each `Frame`, so `pending()` (an overlay that missed `overlay:start`, e.g. a freshly plugged-in monitor) gets the same payload (rule 3: Rust owns the list and the lookup; the UI only draws and hit-tests for the highlight).

### Coordinate rule (the one subtle part)
- macOS `kCGWindowBounds` are global points with a top-left origin, the same space as `MonitorBounds.logical_*`: `local = global − logical_origin`.
- Windows bounds are physical virtual-desktop pixels (DWM extended frame, no invisible border): `local_logical = (global − monitor_physical_origin) / scale`, with `monitor_physical_origin = logical_x × scale` (exact: `logical_x` is the unrounded `x / scale`, and `overlay::ensure_windows` already does this). Put it in one Windows-only helper, `global_physical_to_local()`; don't add a physical origin to `MonitorBounds` (it means nothing on macOS).
- Clip to the monitor. A window spanning two monitors appears on each overlay, clipped; one capture never spans monitors (same as region capture today).

### Overlay states (DESIGN.md tokens; copy goes into DESIGN.md §5)

```
            Space                      Space
 REGION  ─────────►  WINDOW  ─────────────────►  REGION
 (default)           hint: "Click a window · Space for area"
   │ drag+release      │ hover → highlight topmost window under pointer
   │ click → monitor   │ click or Enter on highlight → commit
   │ F → monitor       │ click/Enter with no highlight → nothing (no-op)
   │ Esc → cancel      │ F → monitor   Esc → cancel
   ▼                   ▼
 commit              commit
```
- No windows on this monitor (empty list or listing failed): window mode shows "No windows to capture here · Space for area" and clicks do nothing.
- Reduced motion: the highlight appears without transition.
- Tray "Capture window" → `Mode::Window` → same overlay with `startInWindowMode: true`. No default hotkey (like F1.4).

### Error & rescue map

| Codepath | What can go wrong | Handling | User sees |
|---|---|---|---|
| `platform::list_windows` (mac) | CGWindowList returns null | `Ok(vec![])` + `warn!` with timing | window mode: "No windows to capture here" |
| `platform::list_windows` (win) | `EnumWindows`/DWM call fails | `WindowListError` (thiserror) → logged → empty list | same |
| per-window property read | one window errors (closed mid-list) | skip that window, `debug!` | nothing |
| `to_local` | window fully off this monitor | not in this monitor's list | nothing |
| `commit` with window rect | stale monitor / empty rect | existing `StaleMonitor` / `EmptySelection` | existing toast |
| Free cap reached | capture paused | existing `capture_paused` path | existing locked banner |

No `unwrap()`; region capture never depends on the window list succeeding.

### Security / privacy
Window titles and app names are read for nothing beyond filtering; they are never stored, logged at info level, sent to the overlay or uploaded. The overlay gets rectangles only. One new Tauri command, `overlay_commit_window {monitorId, index}`: it validates the index against the stored list (out of range → `EmptySelection`) and never accepts a rect from the UI. No new server endpoints, no telemetry change (window-capture counts would change the disclosed telemetry, so they're out).

### Performance
Budget: hotkey → overlay < 300 ms (PRD F1.2). Log `window_list::snapshot` time next to the existing grab/encode timings. Expect < 20 ms (mac: one window-list copy, ~30–80 windows; Windows: EnumWindows + four DWM calls per window via xcap's getters, a rect torn by a window moving mid-read is accepted). If it exceeds 30 ms on the cloud Mac, run it on a thread in parallel with `grab_all()`. Don't use xcap's `Window` getters on macOS: each re-copies the window list.
