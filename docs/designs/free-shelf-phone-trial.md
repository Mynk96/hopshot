# Design: Free shelf forever, 7-day phone trial, $19 to keep the phone

Generated by /office-hours on 2026-11-06
Branch: mac-release

Status: APPROVED
Mode: Startup

## Problem Statement

Hopshot is built, signed and buyable, and has zero users. It is pay-first (PRD F8.1, ARCHITECTURE §7.5): a new install is `expired` with capture paused until $19 is paid. So nobody can feel the product before paying, and the founder can't learn who it is for. Meanwhile the shelf on its own competes with Dropshelf (~€4 one-time) and Tokri (free, open source) on Windows, while the phone bridge is the part the PRD itself calls "the thing Hopshot is actually for" (PRD §7).

The change: make capture + shelf + drag free forever, give every install a 7-day trial of the phone features, and sell the phone bridge as the $19 lifetime licence.

## Demand Evidence

- The founder's own pain: phone ↔ laptop screenshot transfer (self-messaging via WhatsApp/email).
- One named person, Rohan Godiyal, plus commenters on a short Reddit description. Their behavior so far: "they said it sounds useful". Nobody asked for a download link, asked to pay, or runs the existing build.
- Verdict: interest, not demand. n=1 real usage (the founder). This design is a bet that a free shelf plus a phone trial produces the usage data that's missing today. It is not validated by that data yet.

## Status Quo

- Founder's workaround: messaging screenshots to themself to move them between phone and laptop.
- What exists for free, by device pair (web research, 2026-11-06):
  - Mac + iPhone: AirDrop and Universal Clipboard, built in.
  - Windows + Android: Phone Link and Quick Share, built in.
  - Windows + iPhone: the weakest pair. Phone Link shows recent iPhone photos and screenshots on the PC, and a "Link to Windows" share option exists, but reports on how well it works conflict. Guides still recommend a cable or iCloud links.
- Desktop-to-web: Win+Shift+S / Cmd+Ctrl+Shift+4 plus paste already skips the saved file in most web apps. Save + file picker only hurts where paste fails, and those apps haven't been listed yet.

## Target User & Narrowest Wedge

- The founder holds that "anyone right now has this problem": anyone who screenshots and then has to save and upload, or move it to or from a phone. I pushed back ("anyone" usually means no one specific). We settled on a testable version: **the segment is unknown, and it is whoever still uses the phone feature on day 7.**
- Wedge: phone ↔ laptop in the moment (this screenshot, to that phone, in two actions, any phone through a browser QR code). The shelf is the free hook that gets the app installed.

## Constraints

- Privacy invariants (CLAUDE.md rule 1) don't change: phone features stay HOP1 end-to-end, and keys stay in URL fragments.
- Limits live only in `config/limits.json` (rule 2): trial length and the free plan's limits go there.
- Rust owns logic (rule 3): plan resolution stays in `limits.rs` / the plan-state code, not React.
- **Backward compatibility with v0.1.x:** `POST /v1/trial/start` must keep returning an already-ended trial (ARCHITECTURE §7.6). v0.1.x builds cache its `endsAt` and unlock capture on an active answer. The new trial must use a **different route and response shape** so old builds never see an active trial.
- **Abuse lesson from `af6ad1f` (2026-10-23):** trials keyed to a client-generated `installId` could be minted by inventing ids. This design knowingly keeps a **rate-limited** version of that hole: trials are granted per client install id, bounded by `server.trialRegistrationsPerIpPerDay`, one vault per trial, and the small `phoneTrial` caps. What it does not keep is the unbounded part. Every trial is a server-side licence row with an expiry, and the token, not the install id, is what's checked on each request.

## Recommended Approach

**Free plan + phone trial** (Approach B, founder's model). Wireframe: see UI below.

### Core idea: a trial is just a short-lived licence
No new credential type. Registration creates a server-side **licence row** with plan `phone_trial` and an `expires_at`, bound to the install through the existing `license_devices` table, and returns a normal licence token. Everything downstream (the `X-Hopshot-License` header, the `secrets::LICENSE_TOKEN` keychain entry, `planForDeviceToken`, `planForInstall`, the vault `owner = install:{id}` chain) already works for licences, so the trial runs through it unchanged. This answers how phones resolve (R1-1), which header and keychain entry are used (R1-5), and what happens on purchase.

### Plan names (server `PlanName`, Rust `Plan`)
| Plan | Who | Local (shelf, capture, drag) | Server (drops, share links, vault, pair, phone → laptop) |
|---|---|---|---|
| `free` | no licence, an ended trial, a refunded or revoked licence | all on | **denied** |
| `phone_trial` | an active trial licence | all on | on, with `limits.phoneTrial` |
| `sync` | a paid `bundle` licence | all on | on, with `limits.sync` |
| `lifetime` | legacy rows only (nothing creates one) | all on | as today |

- **`expired` is retired as a behavior** (R1-8). Refunds, chargebacks and revocations resolve to `free`: the paywall takes the phone away, never the shelf. The name `expired` stays accepted on the wire for v0.1.x builds and is treated exactly like `free`. Refunded and revoked installs are **not** eligible for a new trial, because their `install_id` already has a trial row.
- **Deny by default on the server** (R1-7): `limitsFor` / `vaultLimitsFor` become an exhaustive `switch` with an explicit case per plan, and anything unknown gets zero drops and no vault. Every route gate (drops, vaults, pair, items, live) checks `limits.vault` / `dropsPerDay > 0`, never `plan === "expired"`. API tests cover `free`, an active trial, an expired trial, a refunded licence, and an unknown plan string (CLAUDE.md rule 8).

### Limits (all in `config/limits.json`, no literals)
```json
"phoneTrial": {
  "days": 7,
  "dropTtlOptions": ["24h"],
  "dropsPerDay": 20,
  "vault": true,
  "maxPhones": 1,
  "maxComputers": 1,
  "maxVaults": 1,
  "vaultUploadsPerDay": 50,
  "vaultLiveBytes": 104857600,
  "itemTtlOptions": ["24h"]
},
"server": { "...": "...", "trialRegistrationsPerIpPerDay": 5 }
```
**Abuse bound, by the numbers** (R1-9, R2-1, R2-2). Tokens can be minted with plain HTTP calls, so the bound is per IP. Each trial lasts 7 days, so an IP registering the maximum 5 trials a day holds up to **5 × 7 = 35 active trials** at steady state. With `phoneTrial.maxVaults: 1` (enforced in `POST /vaults` per licence, with an API test), each trial holds at most 100 MiB live: **35 × 100 MiB = 3,500 MiB (≈ 3.67 GB) live per abusing IP**. At R2's $0.015/GB-month that is **≈ $0.055 per month per IP**. Writes: at most 35 × 50 vault uploads + 100 drops (`server.perIpDropsPerDay` caps drops per IP) = **≤ 1,850 Class-A writes per IP per day**. The founder is asked to accept this figure at approval. If not, lower `trialRegistrationsPerIpPerDay` or `phoneTrial.vaultLiveBytes`.

### Registration lifecycle (R1-6)
- **When:** the first time the app reaches the server (first launch if online). It retries at every launch, every 60 min while running, and on any phone-button click until it succeeds. There is no hot loop: a failure waits for the next of those triggers.
- **The 7 days start at successful registration** (`expires_at = server now + days`), not at install time.
- **Route:** `POST /v1/trial/phone` with `X-Hopshot-Install`. This is deliberately **not** `/v1/trial/start`, which keeps answering a dead trial so v0.1.x builds stay locked. It's idempotent per `install_id`: a second call for an install that already has a trial row returns that row's `expiresAt` and issues a fresh token bound to the same licence. A lost keychain token therefore never resets the clock. A brand-new install id does get a new trial, which is the accepted, per-IP-capped risk above.
- **States the user can see** (DESIGN §5 copy to add):
  - Not yet registered (offline): no trial banner. Phone button → "Your 7-day phone trial starts the first time Hopshot is online."
  - Registration refused by the per-IP cap (shared office, CGNAT): plain `free`. Phone button → "Couldn't start a phone trial from this network. Try again tomorrow, or Buy · $19 once."

### Local plan state in Rust (R1-2, R1-3)
- `apps/desktop/src-tauri/src/license.rs` → `plan_state` / `PlanState` / `current_plan`: replace the `token().is_some() → Lifetime` / `None → Expired` logic with **the server's last word**. Every licence-status response (already fetched on launch and every `licenseRecheckDays`) returns `{plan, expiresAt?}`. The desktop stores that in settings (non-secret) and resolves locally:
  - no token, or a cached plan of `free` → `Plan::Free`, `capture_paused: false`;
  - cached `phone_trial` with `now < expiresAt` → `Plan::PhoneTrial`; once past `expiresAt` → `Plan::Free` without waiting for the server;
  - cached `sync` → `Plan::Sync`;
  - cached `lifetime` (legacy licences) → `Plan::Lifetime`.
  - **Offline or disagreeing:** local state only drives UI (tray "Pair phone…" row, phone button, banner). The server refuses anything it hasn't granted, and the next status response overwrites the cache. Capture never depends on the server.
- `capture_paused` stays in the struct but is always `false`. Remove it in a follow-up once nothing reads it.
- `apps/desktop/src-tauri/src/limits.rs`: add the `Plan::Free` and `Plan::PhoneTrial` variants, a `PhoneTrialLimits` struct, and two predicates kept separate (R2-6): `has_server_drops()` (true for `Lifetime`, `PhoneTrial`, `Sync`) gates send-to-phone and share links; `includes_phone()` (true for `PhoneTrial`, `Sync`) gates vault and pairing, replacing `includes_sync()` there. Legacy Lifetime licences keep drops and share links exactly as today. One Rust test per plan × predicate. `drop_ttl_options` / `default_drop_ttl` return the trial's options for `PhoneTrial`. Plus tests.

### Purchase and restore during or after a trial (R1-5)
- Buying on a trial install goes through checkout as today. The webhook creates the `bundle` licence and binds it to the **same `install_id`**; the trial licence row is marked `status = 'superseded'` (not deleted, for attribution).
- `planForInstall`'s query keeps `ORDER BY` but filters to `status = 'active' AND (expires_at IS NULL OR expires_at > now)`, preferring paid plans over `phone_trial`. Then the vault created during the trial (owner `install:{id}`) resolves to `sync` the moment the purchase lands. **Paired phones and vault items carry over with no re-pairing.**
- The desktop replaces `LICENSE_TOKEN` with the purchase's token, as it does today. Restore on a new computer works as today and never touches the trial.

### When the trial ends (R1-11)
- The server resolves the vault to `free`: new phone uploads and new pairings are refused with `403 plan_free`. Existing vault items stay **readable** until their own 24 h TTL and are deleted by the cron as usual. Nothing is deleted early.
- **Phone PWA copy** on a refused upload or pair: "The phone trial on your computer has ended. You can turn this back on from Hopshot on your computer." No buy link on the phone (the purchase belongs to the desktop install).
- **Live sockets:** VaultHub closes a vault's sockets with code `4402 plan_free` the next time it handles an event for a vault that resolves to `free`. The desktop gets that close, refreshes licence status, and drops to `Plan::Free`. No popover is triggered by it.
- **Desktop popover trigger:** only the user's own click on the phone button (or "Pair phone…"). The design no longer depends on "an arriving phone item", because those are refused server-side.

### UI (approved wireframe; reuses the S3 Locked banner slot, no new layout)
Wireframe: `~/.gstack/projects/Mynk96-hopshot/mayankharsani-mac-release-sketch-20261106-153635.png` (copy to `design/trial-states.png` in the repo when implementing).
1. **Trial, more than 1 day left:** "Phone trial · N days left / Send to phone and pairing are on. The shelf stays free forever." `Buy · $19 once` + `Later`. N = `ceil((expiresAt − now) / 24h)`, so a new trial shows 7.
2. **Last 24 h** (`expiresAt − now ≤ 24h`): "Phone trial ends tomorrow / Keep your phone connected for $19 once. 14-day refund." No `Later`. Never modal. Capture is never affected.
3. **`free`:** no banner. The phone button or "Pair phone…" opens a "Phone · $19 once" popover with `Buy` and `Restore`.
- `Later` stores `trialBannerDismissedUntil = now + 24h` in Rust settings (rule 3), not React state.
- Follows DESIGN principle 4 ("calm about time"): no countdown clock, no red.

### Measurement (R1-10, R1-14; replaces old Open Question 4)
Server-side, per trial licence row, with no content, no IP and no file names (privacy rule 1 untouched): `licenses.trial_first_phone_at`, plus a small `trial_usage(license_id, day_index, drops, vault_uploads, pairings)` table where `day_index` = days since `created_at`. Retention: 90 days after `expires_at`, then rows are deleted by the cron. **Attribution:** on purchase for an install with a trial row, the new licence stores `converted_from_license_id`. Disclose all of this in one line on `/privacy`. A "phone event" is a drop, a vault upload or a pairing.

### R2-1 — feasibility (blocking)

**Problem**

> The restated abuse bound (the unmet part of R1-9) is arithmetically wrong. Each trial lasts 7 days (phoneTrial.days), and its 24 h item TTL only recycles space inside a trial that stays active. So an IP that registers 5 trials a day has 5 x 7 = 35 trials active at steady state, not 5. Live storage: 35 x 100 MiB (104857600) = 3,500 MiB (about 3.42 GiB), not 500 MiB. Writes: 35 x (50 uploads + 20 drops) = 2,450 Class-A writes per day, not 350 (drops stay capped at 100 per IP by perIpDropsPerDay, so the real figure is at most 35 x 50 + 100 = 1,850). Cost: about 3.67 GB x $0.015 = about $0.055 per month per IP. Even the stated figure is off: 500 MiB = 0.524 GB x $0.015 = $0.0079, not about $0.007.

**Remedy**

> Restate the bound as registrations/day x trial days x vaultLiveBytes (5 x 7 x 100 MiB = 3,500 MiB live per IP), fix the write count and the cost, and confirm the founder still accepts that figure.

### R2-2 — feasibility (blocking)

**Problem**

> The per-trial caps don't bound a trial. In the code, vaultUploadsPerDay and vaultLiveBytes are counted per vault (routes/items.ts lines 77 and 100), and POST /vaults (routes/vaults.ts lines 51-93) puts no limit on how many vaults one licence or install creates. It only checks vaultLimitsFor(plan).vault. One trial token can therefore create any number of vaults, each with 50 uploads a day and 100 MiB live. The per-IP bound the design relies on (5 trials x 100 MiB) has no ceiling. phoneTrial.maxComputers: 1 limits licence device slots, not vaults.

**Remedy**

> Cap vaults per licence or install (for example one live vault per install, or a phoneTrial.maxVaults key in limits.json enforced in POST /vaults), count it in the abuse bound, and add an API test for the limit.

### R2-3 — feasibility (blocking)

**Problem**

> A trial licence row can't be inserted under the current schema, and the migration list doesn't say how that changes. licenses.customer_id is `TEXT NOT NULL REFERENCES customers(stripe_customer_id)` (migrations/0001_init.sql line 42). A trial created by POST /v1/trial/phone has no Stripe customer, and D1 enforces foreign keys. LicenseRow.customer_id and the deviceStatus query (lib/license.ts) also assume every licence has a customer.

**Remedy**

> Choose and document how trial rows satisfy customer_id: make it nullable for source 'trial' with a matching CHECK, or create a placeholder customer per install. List that change in the D1 migration, and update the TS row types and the queries that join customers.

### R2-4 — feasibility (blocking)

**Problem**

> The migration changes three CHECK constraints on licenses (plan, status, source). SQLite and D1 can't ALTER a CHECK, so this means rebuilding the table: create licenses_new, copy the rows, drop the old table, rename. That has to happen while license_devices.license_id (and claims.license_id) point at licenses(id), and it runs against live production licence data before the desktop release ships. The design presents it as a few column tweaks and gives no rebuild, foreign-key handling, backup or rollback plan.

**Remedy**

> State that the migration rebuilds the licenses table, how it handles the foreign keys (for example PRAGMA defer_foreign_keys inside the migration), how it is tested against a copy of production D1, and the rollback step.

### R2-5 — consistency (blocking)

**Problem**

> The document contradicts itself on af6ad1f's minting lesson. Constraints says the trial 'must be granted to a server-issued device token, not to an id the client makes up', and Dependencies claims trials are 'not grants for any invented install id'. A trial is in fact granted to any invented install id, up to 5 per IP per day. The claim that the design 'answers both of its reasons' supports reversing af6ad1f and is overstated.

**Remedy**

> Rewrite the Constraints bullet and the Dependencies claim to say what is true: trials are granted per client install id, bounded by trialRegistrationsPerIpPerDay and the per-trial caps. Note that this knowingly keeps a rate-limited version of the af6ad1f hole.
