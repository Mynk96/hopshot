# Design: Catch built-in screenshots (⌘⇧4, Win+Shift+S) on the shelf

Generated by /office-hours on 2026-11-18

Status: APPROVED

Supersedes: mayankharsani-master-design-20261116-152447.md

## Problem Statement
Settings → Shelf shows "Catch other screenshots — Add images from the clipboard and ⌘⇧4 / Win+Shift+S to the shelf" as a disabled switch (PRD F1.7, P1). People who keep using the OS shortcut out of habit get nothing on the shelf. The founder wants it built.

## Demand Evidence
Founder request; the switch is visible and greyed out in shipped builds (0.1.12), so every user who opens Settings → Shelf sees a promise that does nothing. No user-reported evidence yet.

## Status Quo
- `settings.catch_other_screenshots` exists (default false); nothing reads it. The UI switch is hard-wired `disabled` in `apps/desktop/src/settings/Settings.tsx`.
- The shelf store already has `Source::Folder` and `Source::Clipboard`.
- `shelf::add_capture(app, path, image)` inserts a capture already saved in `captures/`, always with `Source::Capture`.

## How the OSes behave (research, 2026-11-18)
- **macOS:** ⌘⇧3/⌘⇧4/⌘⇧5 save a file to the folder in `defaults read com.apple.screencapture location` (Desktop if unset). Screenshot files carry the Spotlight attribute `kMDItemIsScreenCapture` (the `com.apple.metadata:kMDItemIsScreenCapture` xattr) on 10.8+.
- **Windows 11:** Snipping Tool (Win+Shift+S) auto-saves to `%USERPROFILE%\Pictures\Screenshots` by default (configurable in Snipping Tool) and also copies to the clipboard; with auto-save off it is clipboard-only. Win+PrtScn saves to the same folder.

## Constraints
- CLAUDE.md rule 1: watching and importing are local. A caught screenshot is then treated like a capture, so with Auto-sync on it reaches paired phones only as HOP1 ciphertext through the existing vault sync.
- Rule 3: logic in Rust (`capture/watch.rs` or `shelf/watch.rs`), commands only toggle.
- Rule 4: platform specifics (folder lookup, screenshot test) in `platform/macos.rs` / `platform/windows.rs`.
- Rule 5: two new direct dependencies, listed under Dependencies with justifications.
- Pay-first: while `capture_paused`, caught screenshots are not added (same toast/locked shelf as a capture).

## Premises (agreed)
1. Watch the OS screenshot folder, not the clipboard. A clipboard watcher sees every copied image and can't tell screenshots apart.
2. Off by default; switched on in Settings → Shelf.
3. While Hopshot is unpaid, caught screenshots are locked like captures.
4. Hopshot copies the screenshot onto the shelf and never moves, edits or deletes the original.

## Approaches Considered
- **A — Poll the folder once a second.** No new dependency; up to 1 s delay and a wake-up every second. Not chosen.
- **B — OS file events via `notify` (chosen).** Instant, idle when nothing happens.
- **C — Spotlight query on Mac + clipboard listener on Windows.** Ruled out: depends on Spotlight and brings back clipboard snooping (premise 1).

## Recommended Approach (B)
1. **Folder lookup** (`platform::screenshot_folder()`):
   - macOS: `com.apple.screencapture` `location` (expand `~`), else `~/Desktop`.
   - Windows: `SHGetKnownFolderPath(FOLDERID_Screenshots, KF_FLAG_DONT_VERIFY)` (follows a moved or OneDrive-redirected Screenshots folder; DONT_VERIFY returns the path even before the folder exists, and no KF_FLAG_CREATE, so Hopshot never creates it). If the call still fails, fall back to `FOLDERID_Pictures` + `\Screenshots`; if even Pictures is missing, Settings shows "Can't find your Screenshots folder." Needs windows-sys features `Win32_UI_Shell` and `Win32_System_Com`. A custom Snipping Tool save folder is not supported in v1; the hint says so.
   - Re-read whenever the watcher starts.
2. **Watcher** (`shelf::watch`): a `notify` recommended watcher, non-recursive, on that folder. Started at launch if the setting is on; started/stopped from `shelf::settings_changed` when the switch flips.
   - **Missing folder:** Windows creates Screenshots only on the first save, so watch its parent non-recursively until it appears, then switch to it. A macOS `location` that doesn't exist falls back to `~/Desktop` and Settings shows the problem line "Can't find <path>. Watching your Desktop instead."
   - **Watcher won't start:** the switch stays on and Settings shows "Hopshot can't watch <folder>." with the error logged.
3. **macOS permission (TCC):** reading `~/Desktop` (or Documents/Downloads) triggers "Hopshot would like to access files in your Desktop folder" on first access. Hopshot touches the folder right when the switch is turned on, so the prompt appears then, not mid-capture. A denial shows up as EPERM when listing the folder; then the switch stays on and Settings shows "Hopshot can't see <folder>. Allow it in System Settings → Privacy & Security → Files and Folders."
4. **Pipeline per event**, in this order:
   1. Resolve the path: for rename events use whichever side exists. Only `.png`, `.jpg`, `.jpeg` (HEIC is not decodable by the `image` crate, so it is skipped).
   2. **Dedupe:** coalesce per source path. An in-flight set keyed on the path alone drops any event for a path that is already settling (notify sends a create and several modifies while bytes land). After settling, a (path, size, mtime) entry is recorded in a 60 s "handled" set only when the file was imported or definitively rejected (wrong type, failed decode); a macOS file without the screenshot flag yet is not recorded, so its later metadata event is still processed.
   3. **Skip Hopshot's own writes:** a short-lived (10 min) set of paths Hopshot wrote into the watched folder (Save as…). Drag staging lives in Hopshot's app data `drag/`, never the watched folder.
   4. **Settle:** wait until the size is unchanged for ~300 ms, at most 5 s; at the cap, try once anyway.
   5. **macOS only:** require the `com.apple.metadata:kMDItemIsScreenCapture` xattr (checked after settling). Windows: everything in Screenshots counts.
   6. **Decode** with `image`; on failure skip and log, with no toast.
   7. **Import:** re-encode to PNG into `captures/` (this drops xattrs, so dragged-out or saved copies are never flagged as screenshots again), insert with `Source::Folder` via `shelf::add_external(app, path, image, Source::Folder)`, sharing `add_capture`'s body.
5. **Delivery, like a capture:** `shelf:highlight`, show the shelf if `show_shelf_on_capture`, `stats::record_capture`, and Auto-sync if on. **Not** copy-to-clipboard: the OS already handled the clipboard, and overwriting it would surprise people.
6. **Locked:** if `license::plan_state().capture_paused`, skip the import and show the existing locked shelf/toast.
7. **UI:** enable the switch in Settings → Shelf.
   - Mac hint: "Adds ⌘⇧4 screenshots from <folder>. They appear once macOS saves them; turn off Show Floating Thumbnail in ⌘⇧5 → Options to make that instant."
   - Windows hint: "Adds Win+Shift+S screenshots saved to <folder>. Turn on auto-save in Snipping Tool if they don't appear."
   - Problem lines from steps 2 and 3 show under the switch.

## Open Questions
- Windows with Snipping Tool auto-save off, or Windows 10: nothing is saved, so nothing is caught. Accepted for v1 (hint text); a clipboard listener scoped to Snipping Tool is a possible later addition.
- A screenshot folder the user changes while Hopshot runs: re-read on each start/toggle; a live change is picked up on next launch.
- Duplicate if the user also has "Copy to clipboard" habits: not affected (clipboard is never read).

## Success Criteria
- Mac: ⌘⇧4 → on the shelf within ~1 s of the file being saved (with Show Floating Thumbnail on, macOS saves it ~5 s later), highlighted; the original stays on the Desktop.
- Mac: dragging a caught item back out, or Save as… onto the Desktop, does not add it again.
- Mac: a non-screenshot image dropped on the Desktop is NOT added.
- Windows 11 (auto-save on): Win+Shift+S → on the shelf within ~1 s, including the very first screenshot (folder created after the switch).
- Mac: denying Desktop access shows the permission line, and nothing crashes.
- Switch off → nothing caught; switch on → works without restart.
- Unpaid → nothing caught, locked banner shown.
- Tests: the filter (extension + screenshot flag), the settle logic, and folder lookup parsing; `cargo check` for both targets.

## Distribution Plan
Ships in the next app version through the existing release flow (tag → staged build → Go live).

## Dependencies
- New crate `notify`: the standard cross-platform file-event crate (FSEvents / ReadDirectoryChangesW), also what the official tauri-plugin-fs watcher uses.
- New crate `xattr` (macOS target only): a safe wrapper over getxattr, already in Cargo.lock transitively, to read the screenshot flag without unsafe code.
- windows-sys features `Win32_UI_Shell`, `Win32_System_Com` for `FOLDERID_Screenshots`.
- Reuses `shelf::add_capture` internals, `stats::record_capture`, `shelf::settings_changed` (PR #24).

## The Assignment
Before building: take five screenshots each way you normally do (Mac ⌘⇧4; Windows Win+Shift+S) and note where each file landed and whether Snipping Tool auto-save is on. That list is the acceptance test for this feature.

## What I noticed about how you think
- You asked to "make scanning very quick" last time and you're asking for this to just work with the shortcut people already use — you design around existing habits instead of asking users to learn Hopshot's hotkey.
- You agreed fast that originals must never be touched, even though "no clutter of saved screenshots" is your pitch: you put trust ahead of the cleverer feature.

## Reviewer Concerns

### R2-1 — completeness (blocking)

**Problem**

> The dedupe key is taken in step 4.2, before settling (step 4.4). While a file is still being written (Windows ReadDirectoryChangesW sends Create at size 0, then several Modify events as bytes land), each event carries a different size/mtime, so none match and each starts its own settle-and-import pipeline; after settling they all see the same final file and import it several times. It is also unclear what counts as 'handled': if an event rejected by the macOS xattr check (step 4.5, e.g. checked before the attribute is written) is recorded, the later metadata event for the same file (setting an xattr does not change size or mtime) is skipped and a real screenshot is never caught.

**Remedy**

> Coalesce per source path: keep an in-flight set keyed on the path alone so a second event for a path already settling is dropped, and record the (path, size, mtime) 'handled' entry only after settling, and only when the file was imported or definitively rejected as not a screenshot (not when the xattr may simply not be written yet).

### R2-2 — feasibility (blocking)

**Problem**

> The missing-folder plan ('Windows creates Screenshots only on the first save, so watch its parent ... until it appears') needs the Screenshots path before the folder exists, but SHGetKnownFolderPath verifies existence by default (KF_FLAG_DONT_VERIFY exists to skip that check), so with default flags the call can fail exactly in the case the plan targets, leaving no path or parent to watch. The design does not state the flag or a fallback.

**Remedy**

> Specify the call flags (e.g. KF_FLAG_DONT_VERIFY, and not KF_FLAG_CREATE so Hopshot doesn't create the folder) or a fallback (FOLDERID_Pictures + \Screenshots) when the lookup fails, and what Settings shows if even the parent is missing.

### R2-3 — completeness (minor)

**Problem**

> On Windows, 'everything in Screenshots counts'. If the user drags a caught item from the shelf into the Screenshots folder in File Explorer, Explorer (not Hopshot) writes the file, so it is not in the self-write set and is re-imported as a new item. The 'does not add it again' success criterion covers only Mac.

**Remedy**

> Accept and note this as a v1 limitation, or also skip files whose content hash/size matches a current shelf item.

### R2-4 — clarity (minor)

**Problem**

> The round-1 text handled macOS's hidden `.Screenshot…` temp file explicitly; the new pipeline drops that note. The temp file has a .png extension, so its create event enters the pipeline; it then vanishes during settle, and the behavior for a path that disappears mid-settle is not stated.

**Remedy**

> Skip dotfiles in step 4.1 and say that a path that disappears during settling is dropped silently.

### R2-5 — consistency (minor)

**Problem**

> Step 5 still calls `stats::record_capture`, whose daily count goes into the insights ping (src/stats.rs), so OS screenshots count as Hopshot captures in telemetry; no decision is recorded.

**Remedy**

> State whether caught screenshots count toward the capture stat sent in the ping, or record them separately/not at all.

### R2-6 — clarity (minor)

**Problem**

> Step 6 still shows the locked shelf/toast for every caught screenshot while unpaid, which pops a pay prompt on each OS screenshot the user did not direct at Hopshot.

**Remedy**

> Decide whether the locked toast appears on every caught screenshot, once per session, or whether the watcher does not run while capture is paused.

### R2-7 — clarity (minor)

**Problem**

> Watcher lifecycle remains under-specified: `shelf::settings_changed` (src/shelf/mod.rs) receives only the new Settings, so start/stop needs a managed, idempotent watcher handle; the settle sleep and decode must run off the notify callback thread; Settings.tsx hard-wires the switch, not only `disabled`.

**Remedy**

> Note the managed watcher state (start if on and not running, stop if off), that imports run on a worker thread, and that the switch binds to `settings.catchOtherScreenshots`.

### R2-8 — consistency (minor)

**Problem**

> PRD F1.7 and the shipped switch copy still say 'Add images from the clipboard and …', while premise 1 drops the clipboard; the design does not say the PRD/DESIGN copy is updated.

**Remedy**

### R2-9 — completeness (minor)
